# SignalForge

Bangkok-only commercial-signal application for Myanmar tender/regulation evidence collection, canonicalization and downstream delivery.

## R5 scope

R5 intentionally starts with one production-enabled source: **S13 MPT Tender Information**. Discovery uses the issuer-owned `https://mpt.com.mm/page-sitemap.xml` and standard TLS. The legacy Tender landing page is context only because the 2026-09-02 Bangkok observation returned an empty content body while the official sitemap exposed real Tender detail pages.

The first source run establishes a baseline: it may store evidence and canonical records but creates **zero customer signals**. Later new or materially changed tenders create `NEW` / `UPDATED` signals.

SignalForge application runs are executed by `signalforge-run-due.service`, whose systemd/resource/identity envelope is generated by `vps-worker-plane`. Each application scheduler Run records the correlated Worker operational Run ID from `/run/worker/apps/signalforge/$INVOCATION_ID.json`.

## Local verification

```sh
python -m unittest -v tests.test_contract tests.test_mpt tests.test_engine
python -m compileall -q signalforge tests
python -m json.tool registry/Source-Registry-v1.yaml >/dev/null
sh -n bin/signalforge
sh -n deploy/deploy-signalforge-release.sh
```

```text
  venvs/

  tmp/

```

The application is installed on **Bangkok only**. Beijing must remain absent. The timer is installed disabled; it is enabled only after Gate O live verification passes.
